# Domain Docs

Before exploring, read the root `GLOSSARY.md`, or `GLOSSARY-MAP.md` if present and the relevant context glossary. Read relevant ADRs in `docs/adr/`; for multi-context repos, also check `src/<context>/docs/adr/`.

If these files don’t exist, proceed silently. Create them when terms or decisions are resolved, not preemptively.

This is a single-context repo: use a root `GLOSSARY.md` and `docs/adr/`.

Use glossary terms in issues, proposals, hypotheses, and test names. If a needed term is missing, reconsider whether it reflects project vocabulary or note the gap for domain modeling.

If a proposal conflicts with an ADR, surface the conflict rather than silently overriding it.
